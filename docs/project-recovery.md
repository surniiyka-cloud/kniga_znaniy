# Команда восстановления проекта «Книга знаний»

Триггерная фраза пользователя: **«Восстанови КЗ»**.

При получении этой фразы:

1. Открыть репозиторий `surniiyka-cloud/kniga_znaniy`.
2. Прочитать `data/version-log.json` и определить фактическую текущую версию проекта.
3. Проверить последние коммиты после/вокруг этой версии, чтобы восстановить последние технические правки.
4. Использовать историю текущего Project-чата как контекст требований к интерфейсу, редактору, структуре карточек и данным.
5. Основной слой ручных правок карточек — `data/admin-overrides.json`; не откатывать уже внесённые override-правки без прямого указания пользователя.
6. Если пользователь даёт новый файл, скриншот, таблицу или фото как более точный источник, он имеет приоритет над старым каталогом и ранее внесёнными предположениями.
7. Не додумывать отсутствующие характеристики. Всё, что нельзя подтвердить по предоставленному источнику, либо оставить без изменения, либо явно вынести пользователю как вопрос/примечание.
8. Формулировки из файлов и скриншотов переносить максимально точно, если пользователь не просит редактуру текста.
9. После фактической правки:
   - проверить затронутые карточки/раздел;
   - увеличить версию;
   - добавить запись в `data/version-log.json`;
   - при необходимости обновить кэш сайта.
10. Продолжать работу с последнего фактического состояния репозитория, а не с версии, которую пользователь мог назвать по памяти.

Короткая команда означает: **восстановить контекст проекта, проверить актуальный GitHub, затем продолжить правки без повторного пересказа всей истории.**
